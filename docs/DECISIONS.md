# 项目决策记录

## DEC-001：两台 PC 均承担开发和测试

- 日期：2026-10-19。
- 决策来源：用户明确要求当前 PC 开发和测试，后续另一台 PC 也开发和测试，使用 GitHub 同步产物。
- 状态：已采用。
- 设备称呼：PC-A 为当前电脑，PC-B 为后续接入的另一台电脑；称呼不绑定开发端、测试端或联机主客机。
- 工作方式：任一 PC 可完成开发、构建、打包、测试和修复；切换设备时依据同一仓库中的提交、任务、交接及测试记录继续，不依赖私人聊天记忆。
- GitHub 同步：代码和文本资料通过 Git；需要跨机复用的 Mod 构建包采用 GitHub Releases 附件交接，附源码提交和 SHA256，不把游戏文件与本地路径提交到仓库。草稿包、预发布测试包与正式发布分开记录，公开发布仍由项目负责人决定。
- 设备验证：各设备独立安装和验证环境；PC-B 尚未接入。双人实测另需确认同时可用的游戏客户端、账号和操作者。
- 替代安排：取消原先专用远程开发设备与固定 PC 测试端的分工，取消按白天开发、晚上测试的交接假设。
- 影响范围：需求书第1、8、9、10、12、13、14节，README、TECH_BASELINE、STATUS及新增COLLABORATION。
- 不受影响：主题与宿主仍待确认；卡牌数值、连招规则、FR/TC验收要求和正式发布门槛不变。

协作细节见 [COLLABORATION](COLLABORATION.md)。本次只更新约定与说明，没有实现产物自动上传或创建发布包。

## DEC-002：最小加载工程采用单一BaseLib 3.3.2依赖

- 日期：2026-10-19；状态：已采用。
- 授权来源：用户要求推进计划第1、2步，交付可重复构建、部署并在游戏中加载的最小工程。
- 选择：游戏v0.107.1、BaseLib 3.3.2、Godot.NET.Sdk 4.5.1、net9.0；不引入第二个Mod框架。采用原生加载入口，工程ID为中性名称Sts2Mod，不据此确认主题与宿主。
- 依据：官方历史发行与项目配置符合本机框架版本；PC-A真实启动成功初始化BaseLib和本项目并读取资源，原生清单可见。RitsuLib不作为当前依赖。
- 约束：NuGet精确引用、锁文件和官方运行时ZIP校验固定版本；原生清单仅支持最低依赖版本，本项目另做版本检查。模板自动部署由显式脚本替代。
- 当前范围：仅加载与资源验证，affects_gameplay为false；正式卡牌开发时必须改为真实值并进行玩法及联机验收。
