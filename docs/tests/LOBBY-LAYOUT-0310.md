## 复现与原因

原生NRemoteLobbyPlayer.OnPlayerChanged在角色变化时创建ScreenPunch，并缓存Position。FlowContainer的首次排列及重排是延迟执行的：若角色更新先于布局，多行会缓存相同的初始位置。随后_Process里的晃动将列表排好的行拉回旧坐标，造成头像和名字一起重叠。行高和头像尺寸本身并无异常，不能只靠缩小头像解决。

使用原生选人屏、玩家列表及NRemoteLobbyPlayer，在同一帧新增四行并将其中三行切换到旅行者，成功复现：首两行及第四行global rect坐标相同，检查失败。日志game-20261021T1629474266681Z.log及其FAIL结果保留，PID4780已退出。静态创建、不触发角色切换时不复现，记录亦保留在.local/lobby0310。

## 修复

TravelerLobbyLayoutPatch对两个原生OnPlayerChanged重载追加窄范围处理：切入或切出旅行者时，原生完成头像、名字、角色名、准备及断线标记更新后取消基于旧坐标的晃动，并请求父Container重新排列。其他角色之间的切换保持原生逻辑。未更改网络消息、成员身份、准备状态、角色模型、头像图片或战斗结算。

修复后四行global rect位置依次为(36,45)、(36,117)、(36,189)、(36,261)，每行310×68，行间4像素；头像48×48，各自独立。新增13项输出检查覆盖双旅行者头像、四人混合角色及名字、中文/长英文名字、原生头像与准备标记、连续帧观察、八次角色来回切换和列表重排。
