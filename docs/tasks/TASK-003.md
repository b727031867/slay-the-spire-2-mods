# TASK-003：集成验收与试玩反馈

状态：**IN_PROGRESS**。2026-10-20在PC-A回归0.1.1，默认无GUI，不安排或启动图形窗口。PC-B的0.1.0单人自动化通过是历史记录，不能直接作为0.1.1通过证据；本轮结果另记报告。

本轮在 PC-B 用真实游戏进程验证并修复：自动打出风牌不推进元素、随后主动风牌正确触发；原生额外回合重置连招次数和派蒙状态；死亡目标不重定向岩雷攻击；基础效果击杀最后敌人时不再发连招与派蒙奖励。

当前验收规则：六张牌及升级；三类元素对双向触发；三类连招共用每人每回合3次；派蒙在共享罕见遗物池，每次成功连招奖励翻倍（4格挡→8、4攻击→8、抽1→2），不是旧版每回合首次+3格挡。

## 任务内容与完成条件

1. **单人机制集成回归**：核对六牌费用、目标、升级、抽牌/消耗顺序；双向组合、共同上限、普通牌穿插、自动/重复结算、额外回合、无效出牌、死亡目标、战斗结束和玩家状态隔离。覆盖范围内有失败先修复再回归；记录实际被测提交及包哈希。
2. **正常获取链路**：验证真实奖励/商店流程中的卡牌与派蒙入库、取得后的牌组/遗物变化、共享遗物池及不重复获取。优先实现无GUI原生流程测试；单纯池注册、直接调试赠牌不替代实际获取证据。
3. **保存、退出与恢复**：用独立测试档按原生支持边界验证六张牌、升级、派蒙保留，重启/重新部署不重复注册或发奖，不残留上一战斗序列。模型序列化往返不等于完整读档；不手工覆盖或删除用户档案，不承诺任意战斗中间点恢复。
4. **持续战斗与数值反馈**：优先使用固定种子的无GUI多场战斗检查长流程、抽牌/能量边界、连招频率、累计奖励及异常；记录数值调整理由并回归受影响用例。少量对局不证明已平衡。
5. **缺陷闭环与可追踪交付**：按严重程度记录复现、修复提交、回归结果、游戏/依赖版本及包SHA256，输出测试报告与交接；不以过滤未知错误获得PASS。
6. **保留的专项验收**：实际画面/文字布局、鼠标交互和人工自然试玩按DEC-005延期，未经用户明确要求不启动GUI；不能用无GUI结果替代。双人主客机按DEC-004另行专项测试，保持NOT_RUN，不阻塞当前单人交付，但最终公开支持联机前必须完成。

本任务的单人逻辑回归可单独记PASS；正常获取、完整读档等尚未执行时仍保留NOT_RUN，不将整体TASK-003标为最终DONE。无GUI测试进程在收集结果后结束，不恢复图形窗口。
