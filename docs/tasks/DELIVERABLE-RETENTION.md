# 成功交付后的制品轮转 · 2026-10-24

用户要求交付成功后自动保留最近3份制品，完成后提交并合入main。本任务使用codex/automatic-deliverable-retention分支。

## 影响与实现

- 基线：94a73f1，既有发布准备、包/快照哈希校验和用户试玩发布门槛。
- 改动：Invoke-ReleasePreparation在测试校验、冻结、上传目录校验及PREPARED报告写入后调用Remove-OldDeliverables，返回并回写Retention结果。失败测试/冻结/上传准备不进入清理；清理异常抛错，新候选和准备报告可供排查及重试。
- 范围：本仓库artifacts直接子目录内的成功交付、历史命名release快照、独立核心交接ZIP及已识别关联副本；按交付时间保留3个不同快照/包身份，过期目录、ZIP、SHA256、准备报告、耗时及.local/workshop副本一并轮转。相同核心仍被保留快照使用时，其核心副本保留；干净的无ZIP核心副本仅在对应交付全部过期后移除。
- 风险控制：先验证完整计划的包/归档/上传哈希、文件清单及绝对路径，拒绝目录联接、未知上传文件和过期报告触发的错误轮转；不修改游戏安装、存档、备份、独立日志、未完成任务或不可识别文件。
- 自定义输出不在artifacts直接子目录时明确SKIPPED并警告；独立构建、冻结或准备目录不算完成交付。已有测试证据通过统一入口-TestResultFile复用即可，不需要重复运行游戏。
